## User Scenarios & Testing *(mandatory)*

### User Story 1 — 이메일 로그인 (Priority: P1)

이메일과 비밀번호로 로그인하면 이전에 접근하려 했던 화면(또는 역할별 기본 홈)으로 이동한다. 잘못된 자격증명과 네트워크 오류는 명확한 메시지로 표시되고 폼은 수정 가능한 상태로 남는다.

로그인 화면 하단에는 "로그인하면 서비스 이용약관 및 개인정보처리방침에 동의하게 됩니다" 문구가 **정보 제공 목적**으로 표시된다. 이 문구는 기존 회원이 이미 동의를 완료한 상태임을 안내할 뿐, 신규 사용자의 실제 약관 동의는 소셜 가입 약관 동의 화면(US3) 또는 이메일 가입 화면(US2)에서 명시적으로 수행된다.

**Why this priority**: 모든 사용자가 서비스를 이용하기 위해 반드시 통과해야 하는 관문. returnTo 복귀는 004에서 명시적으로 미뤄진 S-1b이므로 최우선 완성 대상.

**Independent Test**: 백엔드 없이 MSW로 로그인 성공 응답을 모킹해 returnTo 경로 복귀와 오류 메시지를 RTL로 검증할 수 있다.

**Acceptance Scenarios**:

1. **Given** 미인증 사용자가 `/home`에 접근하려 했을 때, **When** 로그인 화면에서 올바른 이메일·비밀번호로 제출하면, **Then** 세션이 수립되고 `/home`으로 즉시 이동한다 (500ms 이내).
2. **Given** 직접 `/login`에 접근한 USER 사용자가 로그인하면, **When** 인증 성공, **Then** returnTo 없이 `/home`으로 이동한다.
3. **Given** ADMIN 사용자가 로그인하면, **When** 인증 성공, **Then** `/admin`으로 이동한다.
4. **Given** 로그인 폼이 표시된 상태에서, **When** 이메일·비밀번호를 비워 두고 제출하면, **Then** 각 필드에 입력 필요 메시지가 표시되고 서버 요청은 발생하지 않는다.
5. **Given** 올바른 형식이 아닌 이메일을 입력하면, **When** 제출 시도, **Then** 이메일 형식 오류 메시지가 표시된다.
6. **Given** 틀린 비밀번호를 입력하면, **When** 제출, **Then** "이메일 또는 비밀번호가 올바르지 않습니다." 메시지가 표시되고 폼은 재시도 가능 상태를 유지한다.
7. **Given** 네트워크가 단절된 상태에서 로그인을 시도하면, **Then** 네트워크 오류 메시지가 표시되고 폼은 재시도 가능 상태를 유지한다.
8. **Given** 소셜 로그인 버튼(카카오·Google·Apple)이 표시된 상태에서, **When** 버튼을 클릭하면, **Then** 해당 제공자의 인증 페이지로 이동이 시작된다 (소셜 가입 흐름은 US3 참조).
9. **Given** 로그인 화면 하단에 약관 안내 문구가 있을 때, **Then** 문구는 정보용으로만 표시되고 별도 체크박스나 동의 액션은 요구되지 않는다.

### User Story 2 — 이메일 회원가입 (Priority: P1)

이메일·비밀번호와 약관 명시적 동의로 계정을 만든다. 필수 항목(서비스 이용약관·개인정보처리방침·만 14세 이상)에 모두 동의하고 가입이 성공하면 이메일 인증 단계로 자동 진입한다. 중복 이메일과 비밀번호 규칙 위반은 해당 필드에 즉시 표시된다.

**Why this priority**: 신규 사용자 유입의 첫 단계. 약관 동의를 명시적으로 받아야 법적 요건을 충족한다.

**Independent Test**: MSW로 회원가입 성공·중복 이메일·비밀번호 오류 응답을 모킹해 RTL로 흐름을 검증할 수 있다.

**Acceptance Scenarios**:

1. **Given** 가입 폼에서 유효한 이메일·비밀번호를 입력하고 필수 약관(서비스 이용약관·개인정보처리방침·만 14세 이상)에 모두 동의하면, **When** 가입 제출, **Then** 계정이 생성되고 이메일 인증 화면으로 이동한다.
2. **Given** 필수 약관에 하나라도 동의하지 않으면, **When** 가입 제출, **Then** 제출이 막히고 미동의 항목이 강조된다.
3. **Given** "만 14세 이상입니다" 항목에 동의하지 않으면, **When** 가입 제출, **Then** 해당 항목이 필수임을 안내하고 제출이 차단된다.
4. **Given** 이미 가입된 이메일을 입력하면, **When** 가입 제출, **Then** "이미 사용 중인 이메일입니다." 메시지가 해당 필드에 표시된다.
5. **Given** 비밀번호 규칙(최소 8자, 영문+숫자 조합)을 충족하지 않으면, **When** 가입 제출, **Then** 규칙 위반 내용이 메시지로 표시된다.
6. **Given** 가입 폼에서, **When** "약관 전문 보기" 링크를 클릭하면, **Then** 약관 내용이 새 탭 또는 모달로 표시된다.
7. **Given** "모두 동의" 체크박스를 선택하면, **When** 체크, **Then** 필수·선택 항목이 모두 체크된다. 개별 항목을 해제하면 "모두 동의"도 해제된다.

### User Story 3 — 소셜 로그인·가입 (Priority: P2)

소셜 버튼 클릭 후 제공자(카카오·Google·Apple)의 인증을 완료하면 앱으로 복귀한다. **기존 회원**이면 즉시 로그인이 완료된다. **신규 회원**이면 `pendingToken`을 받아 소셜 가입 약관 동의 화면으로 이동하고, 약관에 동의 후 가입과 로그인이 한 번에 완료된다.

소셜 가입 약관 동의 화면은 AuthShell(중앙 카드) 안에 렌더되며, 이메일 가입의 약관 컴포넌트(TermRow: 서비스 이용약관[필수]·개인정보처리방침[필수]·마케팅 수신[선택]·만 14세 이상[필수] + "모두 동의")를 재사용한다. 이메일·비밀번호 입력 필드는 없으며, 신원은 소셜 제공자에서 이미 확인되었다.

SocialCallbackPage는 카카오·Google(GET 쿼리 파라미터 콜백)과 Apple(`response_mode=form_post`, POST form body 콜백) 양쪽을 처리해야 한다. Apple의 경우 `userJson`(초회 로그인 시 provider가 form body로 전달)도 동일 POST로 수신된다. SPA에서 POST 방식 콜백을 수신하는 구체적 구현(예: 백엔드 미들웨어 relay, meta refresh)은 `/speckit-plan` 설계 대상이다.

**Why this priority**: 소셜 로그인은 로그인 화면의 주요 진입 경로(US1 SC#8)와 직결된다. 신규 가입의 법적 동의를 소셜 흐름에서도 누락 없이 수집해야 한다. P2로 설정한 이유: 소셜 OAuth는 제공자별 키 등록·`redirectUri` 화이트리스트 설정이 선행돼야 실제 검증이 가능하며 현재 미설정 상태. 이메일 기반 인증 흐름(US1·US2·US4·US5)을 먼저 완성하고 소셜 흐름은 환경 준비 후 별도 슬라이스로 진행한다.

**Independent Test**: MSW로 `/callback` 응답을 (a) 기존 회원 → 토큰 응답, (b) 신규 → `isNew=true, pendingToken` 응답으로 분기해 두 경로를 RTL로 검증할 수 있다.

**Acceptance Scenarios**:

1. **Given** 사용자가 소셜 로그인 버튼을 클릭하면, **When** `GET /api/v1/auth/{provider}/authorize`(요청에 `redirectUri`=/oauth/callback 포함)가 반환한 `authorizeUrl`로 이동해 제공자 인증을 완료하면, **Then** 제공자가 `redirectUri`(/oauth/callback)로 리다이렉트해 SocialCallbackPage에 `code`와 `state`가 전달된다.
2. **Given** SocialCallbackPage에서 `POST /api/v1/auth/{provider}/callback`을 호출했을 때, **When** 기존 회원임을 응답받으면 (`isNew=false`), **Then** 토큰이 발급되고 004 게이트에 따라 역할별 홈으로 이동한다.
3. **Given** SocialCallbackPage에서 `POST /api/v1/auth/{provider}/callback`을 호출했을 때, **When** 신규 회원임을 응답받으면 (`isNew=true, pendingToken`), **Then** 소셜 가입 약관 동의 화면으로 이동하고 `pendingToken`이 전달된다.
4. **Given** 소셜 가입 약관 동의 화면에서 필수 약관(서비스 이용약관·개인정보처리방침·만 14세 이상)에 모두 동의하면, **When** "가입 완료" 버튼을 클릭하면, **Then** `POST /api/v1/auth/social/complete(pendingToken, consents, ageConfirmed)`가 호출되고 가입과 로그인이 완료되어 004 게이트로 진입한다.
5. **Given** 소셜 가입 약관 동의 화면에서 필수 약관에 하나라도 동의하지 않으면, **When** "가입 완료" 시도, **Then** 가입 완료 버튼이 비활성화 상태이거나 미동의 항목이 강조되어 제출이 차단된다.
6. **Given** 소셜 가입 약관 동의 화면 상단에, **Then** "[제공자 이름]로 가입을 완료하려면 약관에 동의해주세요" 안내 문구가 표시된다.
7. **Given** `state` 값이 앱에서 발급한 값과 다른 콜백이 수신되면 (CSRF 의심), **Then** 오류 화면이 표시되고 콜백 처리가 중단된다.
8. **Given** 소셜 콜백에서 동일 이메일의 이메일 계정이 이미 존재한다는 충돌 응답(409)이 오면, **Then** "해당 이메일로 가입된 계정이 있습니다. 이메일로 로그인해 주세요." 안내와 함께 로그인 화면으로 유도된다.
9. **Given** `pendingToken`이 만료된 상태에서 가입 완료를 시도하면, **Then** 만료 안내와 함께 소셜 로그인을 처음부터 다시 시도하도록 유도한다.

### User Story 4 — 이메일 인증 (Priority: P2)

가입 직후 또는 004의 이메일 미인증 게이트에 의해 인증 화면에 도달한다. 발송된 코드나 링크로 인증을 완료하면 이메일 인증 상태가 갱신되고 다음 단계(온보딩 또는 앱)로 이동한다.

**Why this priority**: 가입→인증→온보딩 흐름의 중간 연결고리. 인증 없이는 앱 진입 불가이므로 가입과 함께 제공해야 한다.

**Independent Test**: MSW로 인증 성공·실패·만료 응답을 모킹해 상태 전이를 검증할 수 있다.

**Acceptance Scenarios**:

1. **Given** 이메일 인증 화면이 표시된 상태에서, **When** 올바른 인증 코드를 입력하면, **Then** `emailVerified`가 `true`로 갱신되고 004 게이트가 다음 경로(온보딩 또는 홈)로 안내한다.
2. **Given** 잘못된 또는 만료된 코드를 입력하면, **When** 확인 제출, **Then** 오류 메시지가 표시되고 재시도 또는 재발송 선택지가 제공된다.
3. **Given** 인증 메일을 받지 못한 경우, **When** "재발송" 버튼을 클릭하면, **Then** 새 인증 메일이 발송되고 성공 안내가 표시된다.
4. **Given** 인증 메일의 링크를 클릭해 앱에 돌아오면, **Then** 인증이 자동 완료되고 다음 단계로 이동한다.

### User Story 5 — 비밀번호 찾기·재설정 (Priority: P2)

비밀번호를 잊은 사용자가 등록된 이메일로 재설정을 요청하고, 코드 또는 링크로 새 비밀번호를 설정한 뒤 로그인 화면으로 돌아간다.

**Why this priority**: 사용자 이탈 방지 필수 기능. 단, P1 화면보다 이용 빈도가 낮아 P2.

**Independent Test**: MSW로 각 단계(요청·확인·설정) 성공 및 오류 응답을 모킹해 3단계 흐름을 검증할 수 있다.

**Acceptance Scenarios**:

1. **Given** 비밀번호 찾기 화면에서 등록된 이메일을 입력하면, **When** 요청 제출, **Then** 재설정 안내 메일이 발송됐다는 확인 메시지가 표시된다 (이메일 존재 여부는 노출하지 않음).
2. **Given** 재설정 코드를 입력하면, **When** 확인 제출, **Then** 새 비밀번호 입력 화면으로 이동한다.
3. **Given** 새 비밀번호를 입력하면, **When** 제출 성공, **Then** "비밀번호가 변경됐습니다." 안내와 함께 로그인 화면으로 이동한다.
4. **Given** 만료된 코드를 입력하면, **Then** 만료 메시지와 함께 재요청 링크가 표시된다.

### User Story 6 — 약관 재동의 (Priority: P2)

004의 `requiresReConsent` 게이트에 의해 재동의 화면에 도달한 사용자가 변경된 약관을 확인하고 동의를 제출하면 게이트가 해제되고 앱으로 진입한다.

**Why this priority**: 법적 요건 충족 흐름. 조건부 발생이지만 발생 시 반드시 완료해야 앱 진입이 가능하다.

**Independent Test**: `requiresReConsent=true` 상태로 MSW 응답을 구성해 재동의 흐름과 게이트 통과를 검증할 수 있다.

**Acceptance Scenarios**:

1. **Given** `requiresReConsent=true` 상태의 사용자가 로그인하면, **When** 004 게이트가 재동의 화면으로 보내면, **Then** 변경된 약관 내용이 표시된다.
2. **Given** 재동의 화면에서 필수 약관에 모두 동의하면, **When** 제출, **Then** `requiresReConsent`가 해제되고 다음 게이트(또는 홈)로 이동한다.
3. **Given** 재동의를 거부·이탈하면, **Then** 앱에 진입하지 못하고 로그아웃 또는 서비스 이용 불가 안내가 표시된다.

---

### User Story 7 — 약관·개인정보 공개 열람 (Priority: P3)

누구든지 로그인 없이 서비스 약관과 개인정보처리방침을 읽을 수 있다. 가입 폼의 약관 링크와 공개 경로 모두에서 진입 가능하다.

**Why this priority**: 법적 필수이지만 별도 상호작용이 없는 읽기 전용 페이지라 다른 기능과 독립적으로 마지막에 구현 가능.

**Independent Test**: `/terms`, `/privacy` 경로가 미인증 상태에서 접근 가능하고 콘텐츠를 렌더하는지 확인.

**Acceptance Scenarios**:

1. **Given** 미인증 사용자가 `/terms`에 접근하면, **Then** 서비스 이용약관 내용이 표시된다.
2. **Given** 미인증 사용자가 `/privacy`에 접근하면, **Then** 개인정보처리방침 내용이 표시된다.
3. **Given** 가입 화면에서 약관 링크를 클릭하면, **Then** 약관 내용을 볼 수 있고 돌아오기가 가능하다.

---

### Edge Cases

- 이미 로그인된 사용자가 `/login`, `/register` 접근 → 004 `GuestOnlyRoute`가 역할별 홈으로 리다이렉트 (005는 처리 불필요)
- 이메일 인증 코드 5회 이상 오류 → 잠금 안내 및 재발송 유도
- 비밀번호 재설정 코드 만료(15분) → 만료 메시지와 재요청 안내
- 소셜 콜백 `state` 불일치 (CSRF 의심) → 오류 화면 표시, 콜백 처리 중단
- Apple 소셜 콜백은 `response_mode=form_post`(HTTP POST, form body)로 수신됨 — 카카오·Google의 GET 쿼리 방식과 다름. SPA 수신 구현 방식은 `/speckit-plan` 설계 대상
- 소셜 가입 중 동일 이메일의 이메일 계정 충돌(409) → 이메일 로그인 유도 안내
- `pendingToken` 만료 후 가입 완료 시도 → 만료 안내 + 소셜 로그인 재시도 유도
- 소셜 가입 약관 동의 화면에서 뒤로 가기(브라우저) → `pendingToken`이 메모리에만 존재하므로 소실; 소셜 로그인을 처음부터 다시 시도하도록 안내
- 재동의 화면에서 뒤로 가기(브라우저) → 여전히 재동의 화면에 머무름 (게이트가 처리)
- 약관 콘텐츠 로딩 실패 → 오류 메시지 + 재시도 버튼
- 로그인·가입 제출 중 화면 이탈 방지 (버튼 비활성화)

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 사용자는 이메일과 비밀번호로 로그인할 수 있어야 한다.
- **FR-002**: 로그인 성공 시 `returnTo` 경로(있는 경우)로 복귀하고, 없으면 역할별 기본 홈으로 이동해야 한다.
- **FR-003**: 로그인 화면에 카카오·Google·Apple 소셜 로그인 진입점이 표시되어야 한다.
- **FR-004**: 소셜 버튼 클릭 시 `GET /api/v1/auth/{provider}/authorize`를 통해 제공자 인증 페이지로 이동하고, 콜백(`/oauth/callback`)에서 `POST /api/v1/auth/{provider}/callback`을 호출해 결과를 처리해야 한다.
- **FR-005**: 로그인 폼은 빈 입력·이메일 형식 오류를 즉시 검증해 필드별 메시지를 표시해야 한다.
- **FR-006**: 잘못된 자격증명(401)과 네트워크 오류(5xx/네트워크 단절)는 구분된 사용자 친화적 메시지로 표시되어야 한다.
- **FR-007**: 로그인 화면에 "로그인하면 서비스 이용약관 및 개인정보처리방침에 동의하게 됩니다" 안내 문구가 정보용으로 표시되어야 하며, 별도 동의 액션은 요구하지 않는다.
- **FR-008**: 이메일·비밀번호·필수 약관 동의(서비스 이용약관·개인정보처리방침·만 14세 이상)를 포함한 이메일 회원가입 폼이 제공되어야 한다.
- **FR-009**: 가입 시 필수 약관과 선택 약관이 구분되어 표시되어야 하며, 필수 약관(만 14세 이상 포함) 미동의 시 가입이 차단되어야 한다.
- **FR-010**: "모두 동의" 체크박스가 제공되어야 하며, 이를 선택하면 모든 항목(필수+선택)이 체크되고 개별 해제 시 연동되어야 한다.
- **FR-011**: 이메일 가입 성공 후 이메일 인증 화면으로 자동 전환되어야 한다.
- **FR-012**: 소셜 콜백 응답이 `isNew=false`(기존 회원)이면 토큰을 발급받고 004 게이트로 진입해야 한다.
- **FR-013**: 소셜 콜백 응답이 `isNew=true`이면 `pendingToken`을 받아 소셜 가입 약관 동의 화면으로 이동해야 한다.
- **FR-014**: 소셜 가입 약관 동의 화면은 AuthShell(중앙 카드) 안에 렌더되며, 상단에 "[제공자]로 가입을 완료하려면 약관에 동의해주세요" 안내 문구가 표시되어야 한다.
- **FR-015**: 소셜 가입 약관 동의 화면의 약관 항목은 이메일 가입의 TermRow 컴포넌트(서비스 이용약관·개인정보처리방침·마케팅 수신·만 14세 이상)를 재사용해야 한다.
- **FR-016**: 소셜 가입 약관 동의 화면에서 필수 항목에 모두 동의한 경우에만 "가입 완료" 버튼이 활성화되어야 한다.
- **FR-017**: 가입 완료 버튼 클릭 시 `POST /api/v1/auth/social/complete(pendingToken, consents, ageConfirmed)`를 호출해 가입과 로그인을 완료해야 한다.
- **FR-018**: 소셜 콜백의 `state` 값이 불일치하면 처리를 중단하고 오류 화면을 표시해야 한다.
- **FR-019**: 이메일 인증 화면에서 코드 입력으로 인증을 완료할 수 있어야 한다.
- **FR-020**: 인증 메일 재발송 기능이 제공되어야 한다.
- **FR-021**: 비밀번호 재설정을 이메일 → 코드 확인 → 새 비밀번호 설정의 3단계로 진행할 수 있어야 한다.
- **FR-022**: `requiresReConsent=true` 상태의 사용자는 변경된 약관에 재동의해야 앱 진입이 가능해야 한다.
- **FR-023**: 서비스 이용약관과 개인정보처리방침이 인증 없이 열람 가능해야 한다.
- **FR-024**: 모든 폼은 제출 중 로딩 상태를 표시하고 중복 제출을 방지해야 한다.
- **FR-025**: 모든 폼 필드는 레이블, 오류 메시지, 키보드 탐색이 충족되어야 한다.

### Key Entities

- **인증 세션**: 로그인 성공으로 수립되는 상태. 사용자 식별자·역할·계정 상태·토큰 쌍으로 구성. 004 authStore가 관리.
- **약관 버전**: 현재 활성화된 서비스 이용약관의 버전 정보. 필수/선택 구분 포함.
- **동의 기록**: 사용자가 특정 약관 버전에 동의한 이력.
- **인증 요청**: 이메일 인증 또는 비밀번호 재설정을 위한 임시 코드·링크의 생명주기.
- **소셜 대기 토큰 (pendingToken)**: 소셜 콜백 후 신규 가입 흐름에서 발급되는 단기 임시 토큰. 약관 동의 완료 전까지 가입 의도를 서버에 연결하는 역할. `/auth/social/complete` 호출 시 소비되며 만료 시 소셜 로그인을 재시도해야 한다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 로그인 응답 수신부터 대상 화면 렌더까지 500ms 이내 (004 S-1c 완성).
- **SC-002**: `returnTo` 경로가 있는 경우 로그인 성공 후 100% 해당 경로로 복귀 (004 S-1b 완성).
- **SC-003**: 잘못된 자격증명 입력 시 3초 이내 오류 메시지가 표시되고 폼이 재사용 가능한 상태를 유지한다.
- **SC-004**: 이메일 가입 → 이메일 인증 → 온보딩 진입까지 화면 전환이 끊기지 않는다.
- **SC-005**: 소셜 신규 가입 흐름에서 약관 동의 없이 가입 완료 요청이 차단되고 (`/auth/social/complete` 미호출), 동의 후 가입과 로그인이 한 번에 완료된다.
- **SC-006**: `requiresReConsent=true` 상태에서 재동의 없이 보호 경로 접근이 차단된다.
- **SC-007**: 모든 폼이 마우스 없이 키보드만으로 완료 가능하다 (Tab 탐색, Enter 제출).
- **SC-008**: 서버 오류(400·401·409·422·5xx)마다 오류 코드가 아닌 사람이 읽을 수 있는 한국어 메시지가 표시된다.
- **SC-009**: 모든 폼 필드에 스크린리더가 인식하는 레이블과 오류 안내가 연결된다.

## Assumptions

- 004 라우팅·인증 골격(AuthShell, ProtectedRoute, GateRoute, GuestOnlyRoute, authStore, returnTo 메커니즘)이 완료된 상태를 전제한다.
- `emailVerified` 상태 갱신은 인증 확인 API 응답 또는 `/me` 재조회로 수행한다.
- 소셜 로그인은 리다이렉트 방식이다. 프론트엔드가 `GET /api/v1/auth/{provider}/authorize`를 `redirectUri`(=/oauth/callback)와 함께 요청하면 백엔드가 `authorizeUrl`(제공자 인증 페이지 URL, `state` JWT 포함)을 반환한다. 프론트엔드는 `authorizeUrl`로 이동하고, 인증 후 제공자가 `redirectUri`로 리다이렉트하면 SPA의 `/oauth/callback`에서 `code`와 `state`를 수신해 `POST /api/v1/auth/{provider}/callback`으로 전달한다.
- `/callback` 응답에 `isNew` 필드가 포함되어 기존/신규 회원을 구분한다. 신규이면 `pendingToken`이 함께 반환된다.
- `pendingToken`은 메모리(예: 라우터 state 또는 단기 Zustand 슬라이스)에만 보관한다. localStorage/sessionStorage에 저장하지 않는다.
- 소셜 가입 약관 동의 화면의 약관 항목: 서비스 이용약관(필수), 개인정보처리방침(필수), 만 14세 이상(필수), 마케팅 수신(선택). 이는 이메일 가입 화면과 동일한 TermRow 컴포넌트를 재사용한다.
- 약관 콘텐츠(이용약관·개인정보처리방침 전문)는 API 또는 백엔드 정적 리소스에서 제공된다고 가정한다. 정적 HTML 하드코딩은 하지 않는다.
- 비밀번호 규칙(최소 8자, 영문·숫자 조합)은 openapi 명세의 서버측 검증과 동일하게 클라이언트에서도 표시한다.
- 이메일 인증 코드 방식은 6자리 숫자 코드(또는 매직 링크)이며, 둘 다 같은 화면에서 처리한다.
- 재동의 화면에서 "거부" 선택 시 로그아웃 처리한다.
- 로그인 화면의 약관 안내 문구("로그인하면 서비스 이용약관 및 개인정보처리방침에 동의하게 됩니다")는 기존 회원을 위한 정보용이며, 신규 사용자의 실제 동의는 이메일 가입(US2) 또는 소셜 가입 약관 동의 화면(US3)에서 명시적으로 수행된다.
- 디자인은 `~/Downloads/Newsift_screens/`의 screens3.jsx(Login/Signup/FindPassword/Legal/Error) 프로토타입을 기준으로 하되, A-2 토큰과 AuthShell 레이아웃을 준수해 프로덕션 스택으로 재구현한다. 소셜 가입 약관 동의 화면은 프로토타입에 미포함이며, SignupScreen 약관 컴포넌트 재사용으로 구현한다.
- 소셜 OAuth 연동(`/authorize`, `/callback`, `/complete`)이 백엔드에 미구현된 경우 B-3 이슈 등록 후 소셜 버튼 비활성 stub 처리한다.
