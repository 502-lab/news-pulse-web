# Feature Specification: 006 뉴스 홈 (W-U-01)

**Feature Branch**: `006-news-home`

**Created**: 2026-06-23

**Status**: Draft

**Input**: User description: "006단계: USER 메인 화면 '뉴스 홈'(화면 코드 W-U-01, 웹 전용)의 기능 명세를 작성해줘. (참조 디자인: Newsift_screens/screen-newshome.jsx, user-01-home-WU01.html)"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 핵심 속보 즉시 확인 (Priority: P1)

로그인한 USER가 뉴스 홈에 진입하면, 별도 조작 없이 화면 최상단에서 가장 중요한 속보 1건(제목·출처·시간)을 바로 확인하고, "바로 읽기"로 곧장 해당 기사로 진입할 수 있다.

**Why this priority**: "처음 진입 화면에서 핵심 속보를 가장 먼저 파악한다"는 화면의 1차 목적이며, 다른 영역 없이도 단독으로 가치를 제공하는 가장 단순한 슬라이스다.

**Independent Test**: 뉴스 홈에 진입해 속보 배너만 렌더링된 상태로도 "속보 1건 확인 → 바로 읽기 클릭 → 기사 진입"이 완결적으로 검증 가능하다.

**Acceptance Scenarios**:

1. **Given** USER가 `/home`에 진입했을 때, **When** 화면이 표시되면, **Then** 화면 최상단에 속보 배지·기사 제목·출처·시간·"바로 읽기" 진입 동작이 있는 배너 1개가 보인다.
2. **Given** 속보 배너가 표시된 상태에서, **When** "바로 읽기"를 클릭(또는 키보드로 활성화)하면, **Then** 해당 기사로 이동한다.

---

### User Story 2 - 카테고리별 기사 탐색과 AI 요약으로 빠른 판단 (Priority: P1)

USER가 전체/기술/경제/정치/스포츠/문화 중 관심 카테고리를 선택해 기사를 좁혀 보고, 각 기사의 AI 한 줄 요약만으로 더 읽을지 빠르게 판단한다.

**Why this priority**: 화면의 본문을 구성하는 핵심 탐색 경험이며, 속보 배너 다음으로 가장 많은 시간을 머무는 영역이다. 단독으로도 "카테고리 탐색 + 빠른 판단"이라는 완결된 가치를 제공한다.

**Independent Test**: 카테고리 필터와 뉴스 카드 목록만 렌더링된 상태로 "필터 선택 → 목록 갱신·건수 표시 → 카드의 AI 요약 확인"이 완결적으로 검증 가능하다.

**Acceptance Scenarios**:

1. **Given** USER가 뉴스 홈에 있을 때, **When** 카테고리 필터 중 하나(예: 기술)를 선택하면, **Then** 해당 카테고리 기사만 목록에 남고 결과 건수가 갱신된다.
2. **Given** 특정 카테고리를 선택한 상태에서, **When** 다시 "전체"를 선택하면, **Then** 모든 카테고리 기사가 다시 표시된다.
3. **Given** 선택한 카테고리에 해당하는 기사가 없을 때, **When** 목록 영역을 보면, **Then** 빈 상태 안내가 표시된다.
4. **Given** 뉴스 카드가 표시된 상태에서, **When** 카드를 보면, **Then** 썸네일·카테고리 배지·제목·AI 한 줄 요약·출처·시간·조회수가 모두 표시된다.
5. **Given** 뉴스 카드를 클릭(또는 키보드로 활성화)하면, **When** 동작이 수행되면, **Then** 해당 기사로 이동한다.

---

### User Story 3 - 관심 기사 북마크 (Priority: P2)

USER가 마음에 드는 기사를 북마크하고 즉시 시각적 피드백(아이콘 변경 + 토스트)을 받는다. 이번 단계는 화면 세션 내 in-memory 토글만 구현하며, 새로고침 후 복원과 영속 저장은 후속 단계에서 다룬다.

**Why this priority**: 탐색(US2) 이후에 따라오는 보완 행동이며, 탐색 경험이 없어도 북마크 토글 자체는 독립적으로 테스트 가능하다.

**Independent Test**: 뉴스 카드 1개와 북마크 토글만으로 "토글 → 즉시 피드백(아이콘 변경 + 토스트)"이 완결적으로 검증 가능하다.

**Acceptance Scenarios**:

1. **Given** 북마크되지 않은 기사 카드에서, **When** 북마크 컨트롤을 토글하면, **Then** 북마크 상태가 켜지고 사용자에게 즉시 피드백(아이콘 변경 + "북마크에 저장했어요" 토스트)이 표시된다.
2. **Given** 북마크된 기사 카드에서, **When** 북마크 컨트롤을 다시 토글하면, **Then** 북마크가 해제되고 해제됨을 알리는 피드백("북마크를 해제했어요" 토스트)이 표시된다.

---

### User Story 4 - 위젯 패널로 추가 정보 파악 및 이동 (Priority: P2)

USER가 본문 탐색과 별개로 우측 위젯 패널에서 지금 뜨는 인기 키워드, 최신 속보 타임라인, 오늘의 AI 브리핑을 훑어보고 관심 가는 항목을 클릭해 더 깊이 들어간다.

**Why this priority**: 본문(US1·US2)을 보완하는 부가 정보 영역으로, 본문 없이도 위젯 패널 자체만으로 "훑어보기 + 클릭 진입"이라는 독립적 가치를 제공한다.

**Independent Test**: 위젯 패널 3종만 렌더링된 상태로 "키워드 Top5 확인 → 클릭 → 이동", "속보 타임라인 확인 → 클릭 → 이동", "AI 브리핑 확인"이 각각 완결적으로 검증 가능하다.

**Acceptance Scenarios**:

1. **Given** 뉴스 홈에 진입했을 때, **When** 우측 패널을 보면, **Then** 실시간 인기 키워드 Top 5, 최신 속보 타임라인, 오늘의 AI 브리핑 3개 위젯이 모두 표시된다.
2. **Given** 인기 키워드 목록에서, **When** 키워드 하나를 클릭(또는 키보드로 활성화)하면, **Then** `/search?keyword=<kw>` 라우트로 이동한다(검색 결과 페이지는 빈 스텁으로 표시됨, 실제 결과 구현은 후속 단계).
3. **Given** 속보 타임라인 목록에서, **When** 항목 하나를 클릭(또는 키보드로 활성화)하면, **Then** 해당 기사로 이동한다.
4. **Given** 오늘의 AI 브리핑 위젯에서, **When** 위젯을 보면, **Then** 요약 문장들이 묶여서 표시된다(클릭 동작 없음).

---

### Edge Cases

- 카테고리를 전환했는데 해당 카테고리에 기사가 0건이면 빈 목록이 아니라 빈 상태 안내("해당 카테고리 기사가 없어요" 류)가 보여야 한다.
- 북마크를 토글한 직후 새로고침하면 초기화된다(이번 단계는 비영속, 새로고침 후 복원은 후속 단계).
- 화면 폭이 좁아질 때 카드 열은 3→2→1로 줄고, 더 좁아지면 본문/위젯 패널이 세로로 쌓여야 하며, 어떤 폭에서도 요소 겹침·잘림·불필요한 가로 스크롤이 발생하면 안 된다.
- 키보드만 쓰는 사용자가 필터·카드·배너·위젯 항목·북마크 컨트롤 전부에 Tab으로 도달하고 Enter/Space로 활성화할 수 있어야 하며, 포커스 표시가 보여야 한다.
- 카드 전체가 "기사 열기" 동작을, 카드 내부의 북마크 컨트롤이 별도 동작을 담당하는 경우, 두 동작은 서로 다른 인터랙티브 요소가 중첩되지 않는 구조로 구현되어야 한다(참조 디자인의 마크업을 그대로 복제하지 않는다 — Assumptions 참고).

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 시스템은 로그인한 USER가 `/home`에 진입하면 앱 공용 GNB 헤더 아래에 본문(좌)·위젯 패널(우) 2단 구성의 뉴스 홈 화면을 표시해야 한다.
- **FR-002**: 시스템은 핵심 속보 배너에 가장 우선순위 높은 속보 기사 1건(제목·출처·시간)을 표시하고, "바로 읽기" 동작으로 해당 기사로 이동할 수 있어야 한다.
- **FR-003**: 시스템은 전체·기술·경제·정치·스포츠·문화 6개 카테고리 필터를 제공해야 하며, 필터 선택 시 해당 카테고리 기사만 노출하고 노출된 기사 건수를 표시해야 한다.
- **FR-004**: 시스템은 선택된 카테고리에 해당하는 기사가 없을 때 빈 상태 안내를 표시해야 한다.
- **FR-005**: 시스템은 각 뉴스 카드에 썸네일, 카테고리 배지, 제목, AI 한 줄 요약, 출처, 게시 시간, 조회수, 북마크 상태/토글 컨트롤을 표시해야 한다.
- **FR-006**: 사용자는 뉴스 카드의 북마크 컨트롤로 북마크 상태를 토글할 수 있어야 하며, 토글 즉시 시각적 피드백(아이콘 상태 변경 + 토스트 알림)을 받아야 한다.
- **FR-007**: 북마크 상태는 화면 세션 내에서만 유지된다(새로고침 시 초기화). 영속 저장(localStorage/서버)은 후속 단계 범위로 이관된다.
- **FR-008**: 시스템은 위젯 패널에 실시간 인기 키워드 Top 5를 순위와 함께 표시해야 하며, 키워드 클릭 시 `/search?keyword=<kw>` 라우트로 이동해야 한다(검색 결과 페이지는 빈 스텁, 실제 구현 후속).
- **FR-009**: 시스템은 위젯 패널에 최신 속보 타임라인(시간·카테고리·헤드라인)을 표시해야 하며, 항목 클릭 시 해당 기사로 이동해야 한다.
- **FR-010**: 시스템은 위젯 패널에 오늘의 AI 브리핑(요약 문장 묶음)을 표시해야 한다.
- **FR-011**: 시스템은 GNB의 5개 탭(홈/트렌드 리포트/편향 분석/내 인사이트/주간 브리핑)을 모두 노출하고 "홈" 탭을 활성 상태로 표시해야 한다. GNB 자체의 구조·동작은 기존 공용 레이아웃을 그대로 재사용하며 본 기능에서 변경하지 않는다.
- **FR-012**: 시스템은 화면 폭에 따라 뉴스 카드 열을 3→2→1로 줄이고, 더 좁은 폭에서는 본문/위젯 패널을 세로로 쌓아 표시해야 하며, 모든 폭에서 콘텐츠 겹침·잘림·불필요한 가로 스크롤이 없어야 한다.
- **FR-013**: 화면의 핵심 동작(카테고리 필터 선택, 배너·기사·위젯 항목 열기, 북마크 토글)은 모두 키보드만으로 수행할 수 있어야 하며, 포커스 위치가 시각적으로 식별 가능해야 한다.
- **FR-014**: 아이콘 전용 컨트롤(북마크 토글 등)은 접근 가능한 이름을 가져야 하고, 기사 썸네일 이미지는 대체 텍스트를 가져야 한다.
- **FR-015**: 인터랙티브 요소는 서로 중첩되지 않아야 한다. 카드 전체를 여는 동작과 카드 내부 북마크 토글처럼 서로 다른 동작을 하나의 인터랙티브 요소 안에 또 다른 인터랙티브 요소로 중첩해 구현해서는 안 된다.
- **FR-016**: 화면 구성에 쓰이는 색상·간격·테두리 반경·타이포그래피는 프로젝트에 기존 정의된 디자인 토큰만 사용해야 하며, 임의 값을 사용해서는 안 된다.
- **FR-017**: 화면은 기존 공용 UI 컴포넌트(카드, 배지, 빈 상태, 아이콘 등)를 재사용해 구성해야 하며, 동일한 역할을 하는 범용 UI 컴포넌트를 새로 만들어서는 안 된다. 화면 전용 조합 컴포넌트(예: 속보 배너, 카테고리 필터, 위젯 3종)는 새로 만들 수 있으나, 내부적으로 기존 공용 컴포넌트를 재사용해야 한다.
- **FR-018**: 이번 단계의 모든 데이터(기사, 인기 키워드, 속보 타임라인, AI 브리핑)는 목데이터로 제공되며, 백엔드 비동기 호출에 따른 로딩 상태 처리는 이번 범위에 포함하지 않는다.

### Key Entities

- **NewsArticle**: 뉴스 카드·속보 배너·속보 타임라인이 공유하는 기사 1건. 카테고리, 제목, AI 한 줄 요약, 출처, 게시 시간, 조회수, 속보 우선순위 여부를 가진다.
- **Category**: 전체를 포함한 6개 고정 분류(전체/기술/경제/정치/스포츠/문화) 중 하나로 기사를 묶는 필터 기준.
- **TrendingKeyword**: 순위, 키워드, 언급량(또는 증감 표시)을 가지는 인기 키워드 1건.
- **BreakingTimelineItem**: 시간, 카테고리, 헤드라인을 가지며 특정 NewsArticle과 연결되는 속보 타임라인 항목.
- **AIBriefing**: 오늘의 AI 브리핑을 구성하는 요약 문장들의 묶음.
- **BookmarkState**: 사용자가 북마크한 NewsArticle id의 집합. 이번 단계는 비영속 in-memory(`useState`)로 관리되며 새로고침 시 초기화된다. 영속 저장은 후속 단계.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 사용자는 화면 진입 즉시 추가 조작 없이 핵심 속보 1건과 6개 카테고리의 기사 목록을 확인할 수 있다.
- **SC-002**: 카테고리 필터를 바꾼 직후 1초 이내에 해당 카테고리 기사 목록과 결과 건수가 화면에 반영된다.
- **SC-003**: 기사가 없는 카테고리를 선택한 모든 경우에 빈 목록이 아닌 빈 상태 안내가 표시된다.
- **SC-004**: 북마크를 토글하면 즉시 아이콘 상태가 변경되고 토스트 피드백(북마크에 저장했어요/해제했어요)이 표시된다. 새로고침 후 복원은 이번 단계 범위 밖이다(후속 단계).
- **SC-005**: 위젯 패널의 인기 키워드·속보 타임라인·AI 브리핑 3종이 화면 진입 시 항상 모두 표시되며, 키워드 클릭은 `/search` 라우트로(빈 스텁), 속보 항목 클릭은 해당 기사로 이동한다.
- **SC-006**: 데스크톱(3열)·태블릿(2열)·모바일(1열, 본문/위젯 세로 스택) 폭 어디에서도 콘텐츠 겹침·잘림·가로 스크롤이 발생하지 않는다.
- **SC-007**: 마우스 없이 키보드만으로 카테고리 필터 변경, 배너·기사·위젯 항목 열기, 북마크 토글까지 모든 핵심 동작을 완료할 수 있다.
- **SC-008** *(회귀 방지 — 003 재발 금지)*: 완성된 화면을 W-U-01 참조 디자인과 나란히 대조했을 때 레이아웃 배치·간격·색상·타이포그래피가 일치한다.
- **SC-009** *(회귀 방지 — 003 재발 금지)*: 이 화면 구현으로 인해 프로젝트의 범용 UI 컴포넌트 영역에 새로 추가된 컴포넌트가 없다(화면 전용 조합 컴포넌트는 제외).

## Out of Scope

- 기사 상세 화면의 완성된 구현, 기사 비교 뷰, 트렌드 리포트, 편향 분석, 내 인사이트, 주간 브리핑 — GNB에 탭 노출과 기존에 마련된 진입 경로(라우팅)만 유지하고, 화면 자체의 완성은 후속 단계에서 다룬다.
- 모든 ADMIN(운영자) 화면.
- GNB 상단의 자유 텍스트 검색 입력 및 그 실제 검색 결과 페이지(검색창은 계속 숨김 상태 유지).
- 백엔드 실데이터 연동, 비동기 로딩 상태(스켈레톤 등) 처리.
- 북마크 영속 저장(localStorage 클라이언트 영속 및 서버 저장) — 이번 단계는 화면 내 in-memory 토글+토스트 피드백만 구현한다. 영속 구현과 그 도구 선택은 후속 단계로 이관한다.
- 검색 결과 페이지의 실제 구현(목데이터 필터링, 결과 목록 UI) — 이번 단계는 `/search` 라우트 등록 + 빈 스텁만 포함한다.
- 테마 전환/다크 모드.

## Anti-Goals (003 실패 재발 방지)

과거 메인 화면(003) 시도에서 반복된 실패를 이번 수용 기준에 명시적으로 반영한다.

| 003에서 반복된 실패 | 이번 명세에서의 방지 장치 |
|---|---|
| 레이아웃 배치가 기준 디자인과 다르게 나옴 | FR-001, SC-001, SC-008 |
| 간격·색·타이포 디테일이 무시됨 | FR-016, SC-008 |
| 기존 공용 컴포넌트를 쓰지 않고 기본형으로 새로 작성함 | FR-017, SC-009 |
| 반응형이 시도되지 않음 | FR-012, SC-006 |

## Assumptions

- 모든 데이터(기사, 인기 키워드, 속보 타임라인, AI 브리핑)는 목데이터이며, 실제 백엔드 연동은 후속 단계 과제다.
- 북마크 상태는 이번 단계에서 화면 세션 내 in-memory(비영속)로만 관리한다. localStorage 클라이언트 영속 및 백엔드 영속 연동은 모두 후속 단계 범위로 이관한다. 백엔드 북마크 API 부재는 CLAUDE.md B-4에 기록되어 있다.
- 인기 키워드 클릭 시 `/search?keyword=<kw>` 라우트로 이동한다. 이 라우트는 이번 단계에서 빈 스텁("검색 결과 준비 중")으로만 등록되며, GNB 상단 자유 텍스트 검색(박스 숨김 유지)과 마찬가지로 실제 결과 구현은 후속 단계에서 다룬다.
- 속보 배너, 속보 타임라인 항목, 뉴스 카드 클릭은 모두 기존에 라우팅이 마련된 기사 상세 경로로 이동한다. 기사 상세 화면 자체의 완성된 구현은 후속 단계에서 다룬다.
- GNB(상단 헤더)는 이미 구현된 공용 레이아웃을 그대로 재사용하며, 본 기능에서 GNB 자체의 구조나 동작을 변경하지 않는다.
- "가장 중요한 속보 1건"은 목데이터 중 우선순위가 가장 높은(또는 가장 최근) 항목으로 선정하며, 실제 중요도 산정 로직은 범위 밖이다.
- 화면 전용 조합 컴포넌트(속보 배너, 카테고리 필터, 위젯 3종, 카드 변형 등)는 새로 작성할 수 있으며, 이는 "신규 범용 UI 컴포넌트 금지" 수용 기준의 예외로 간주한다. 단, 내부적으로 기존 공용 컴포넌트를 재사용해야 한다.
- 참조 프로토타입의 마크업 구조(예: 버튼 내부에 중첩된 버튼형 북마크 컨트롤)는 접근성 요구사항(인터랙티브 요소 중첩 금지)과 충돌하므로 그대로 복제하지 않으며, 동일한 시각적 결과를 유효한 인터랙티브 구조로 재구현한다.
