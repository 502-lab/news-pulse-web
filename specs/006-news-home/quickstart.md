# Quickstart: 006 뉴스 홈 (W-U-01) 검증

## 사전 준비

```bash
pnpm install
pnpm dev
```

브라우저에서 로그인 후(USER 계정) `/home`으로 이동, 또는 로그인 화면에서 정상 로그인 시 자동으로 `/home`에 도착한다.

## S-1. 핵심 속보 배너 (US1)

1. `/home` 진입 → 화면 최상단에 속보 배지·제목·출처·시간·"바로 읽기" 버튼이 있는 배너 1개 확인.
2. "바로 읽기" 클릭(또는 Tab으로 포커스 후 Enter) → `/articles/:id`로 이동 확인.

## S-2. 카테고리 필터 + AI 요약 카드 (US2)

1. 카테고리 필터에서 "기술" 선택 → 카드 목록이 기술 카테고리만 남고 결과 건수가 갱신되는지 확인.
2. 기사가 없을 만한 카테고리가 있다면 선택해 `EmptyState`가 뜨는지 확인(목데이터 구성에 따라 전 카테고리에 최소 1건씩 있을 수 있음 — 이 경우 `data-model.md` 기준으로 의도적으로 0건인 카테고리를 목데이터에 1개 포함해 테스트 가능하게 한다).
3. "전체" 재선택 → 전체 기사 복원 확인.
4. 카드에 썸네일·카테고리 배지·제목·AI 한 줄 요약(🤖 AI 배지)·출처·시간·조회수가 모두 보이는지 확인.
5. 카드(북마크 버튼 제외 영역) 클릭 → `/articles/:id` 이동 확인.

## S-3. 북마크 토글 + 토스트 (US3)

> 이번 단계는 in-memory 토글만 구현한다. 새로고침 시 초기화(정상 동작). 영속 저장은 후속 단계.

1. 카드 우상단 북마크 버튼 클릭 → 아이콘 색 변경 + 토스트("북마크에 저장했어요") 확인.
2. 같은 버튼 다시 클릭 → 해제 + 토스트("북마크를 해제했어요") 확인.
3. 페이지 새로고침(F5) → 북마크 상태가 초기화되는 것이 정상(이번 단계 비영속).

## S-4. 위젯 패널 (US4)

1. 우측 패널에 "지금 뜨는 키워드"(Top5), "속보 타임라인", "오늘의 AI 브리핑" 3개가 모두 보이는지 확인.
2. 키워드 하나 클릭 → `/search?keyword=...`로 이동, "검색 결과 (준비 중)" 스텁 페이지가 보이는지 확인(이번 단계 결과 구현 없음).
3. 속보 타임라인 항목 클릭 → `/articles/:id`로 이동 확인.
4. AI 브리핑 항목은 클릭 동작이 없어야 함(요약 문장만 표시).

## S-5. 반응형 (FR-012, SC-006)

브라우저 폭을 조절하며 확인(또는 DevTools 반응형 모드):

- ≥1280px: 본문(좌)/위젯(우) 8:4 가로 배치, 카드 3열, 콘텐츠가 1320px에서 멈추고 가운데 정렬(그 이상 넓혀도 카드가 더 안 늘어남).
- 1280px 미만: 위젯 패널이 본문 아래로 내려가 세로 배치.
- 폭을 계속 좁히며 카드 열이 줄어드는지 확인(중간에 일시적으로 늘어났다가 다시 줄어드는 구간이 있을 수 있음 — `plan.md` 반응형 설계 절의 "알려진 트레이드오프" 참고, 결함 아님).
- 모든 폭에서 가로 스크롤바가 생기지 않는지, 텍스트/카드가 잘리거나 겹치지 않는지 확인.

## S-6. 접근성 (FR-013~015)

1. 마우스를 쓰지 않고 Tab만으로 카테고리 필터 → 카드 → 북마크 버튼 → 위젯까지 전부 도달 가능한지 확인, 포커스 링이 보이는지 확인.
2. 카드에 Tab으로 포커스했을 때 카드 열기와 북마크 버튼이 "각각 별도의 Tab 정지점"인지 확인(버튼 안에 버튼이 중첩되어 있지 않은지 — 개발자도구로 DOM 구조 확인: 카드 링크/버튼과 북마크 버튼이 형제 요소여야 한다).
3. 북마크 버튼에 `aria-label`이 있는지, 썸네일에 대체 텍스트가 있는지 스크린리더 또는 접근성 트리(Accessibility Tree) 패널로 확인.

## 자동 검증

```bash
pnpm tsc --noEmit
pnpm build
pnpm test src/__tests__/homePage.test.tsx
```

세 명령 모두 통과해야 한다(검증 기준에 tsc·build·vitest 포함).
